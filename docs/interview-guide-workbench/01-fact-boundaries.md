## 1. 统一术语

| 术语 | 本文含义 | 不应写成 |
|---|---|---|
| 统一 ReAct 内核 | 承载观察、决策、工具执行、结果回填和终态处理的共享执行骨架 | 单纯的 Prompt 模板 |
| 历史完整实现 | 主仓库 `d565ca...` 及经核对与其对应或兼容的相关插件实现 | 混合不同版本接口和后续能力的假想实现 |
| 自动注入 | turn 开始时按当前请求检索并加入受控记忆材料 | 把全部历史放进上下文 |
| 按需补搜 | Agent 在执行过程中显式调用记忆工具补充线索 | 自动注入的同义词 |
| 原文取证 | 根据真实来源身份回查原始消息或事件 | 只返回不可追溯摘要 |
| 图关联补全 | 从已命中线索扩展相关历史关系 | 独立的第三份搜索结果列表 |
| 工具目录 | 可搜索的能力元数据集合 | 当前轮全部可调用工具 |
| 当轮解锁 | 当前执行 attempt 内使命中工具进入后续实际模型请求的受限 Schema 集合，仍受容量约束 | 只返回工具名称；永久修改全局权限；保证全部命中工具同时可见 |
| 逻辑交互单元 | 用户消息、模型工具调用、工具结果及其完成边界 | 任意固定条数消息 |
| 模型摘要与近期保留 | 对较旧已完成交互生成/更新摘要，同时保留近期内容和原始记录 | 仅按固定窗口丢弃旧消息；工具协议完整就等于摘要语义无损 |
| 运行观测 | 采集、存储或展示某次运行的使用量与状态 | 已经证明某设计使效果提升 |
| 主动发送授权 | 只有显式终态动作才能触发发送 | 模型输出任意 final text 即发送 |
| 官方 Verifier | Terminal-Bench 对任务完成状态的外部判定器 | LLM 自评或文本相似度 |
| accepted projection | 从 WAL 和有效运行中生成可接受的最终任务投影 | 多次 benchmark 结果的随意拼接 |

- "评测链路能够把 26 个有效失败、3 个 Provider fallback 和 1 个 Verifier 基础设施失败分开归因。"
- "Akasha 隔离重放中，9,556 条所需 embedding 全部有效，两个 hash seed 下 11 个冻结 query 得到相同 canonical logical state。"

第二、三句分别属于闭环归因事实和隔离一致性验证，不能转写为用户效果或记忆准确率。

## 4. 不得无依据使用的结论

- "记忆准确率显著提升。"
- "三路检索结果加权融合后返回。"
- "压缩后 token 降低了 X%。"
- "缓存命中率提升了 X%。"
- "主动推送准确率/采纳率达到 X%。"
- "系统能够自动解决新旧事实冲突。"
- "Terminal-Bench 的 3 个 fallback 和 1 个 Verifier 故障都是 Agent 做错了。"
- "历史 63/89 与当前 59/89 可以合并成更高成绩。"

效果数字只有取得支持对应主张的数据、核对口径并经确认后才能使用。本清单是编写者检查项，正文无需逐条复述"不能说"。

## 5. 版本与基线

- 主仓库基线固定 `d565ca44356b5d52fe8d00f8cb008c14fff56c0b`（源码副本 `F:/agent/akashic-agent-d565`）；不混入当前主干迁移实现的类名、路径和状态结构。
- [akashic-plugins](https://github.com/akashic-plugins) 属相关材料：只读与基线对应或兼容的实现并记录版本；插件当前页面、更新时间或"兼容"标签不能单独证明基线已具备某能力。
- Observe 钉子：2.0.0 依赖后续 Message runtime，与 d565 基线不直接兼容；1.2.0 为历史运行记录线索（核对结论见 `packets/04-tools-and-context.md`）。
- Terminal-Bench 固定结果为 59/89 = 66.3%；历史 High 轨道 63/89 = 70.8% 仅作内部核查线索，不与最终结果合并、替代或设为默认面试题。
- LongMemEval、PersonaMem 只能作为未来规划，不得写成当前成果。

## 6. 技术比较基准（支撑层"替代方案对比"的起点）

- **混合检索与重排**：常见方案为稠密向量 + BM25 + RRF 排名融合，按需加入 cross-encoder 重排；bi-encoder 负责独立编码检索，cross-encoder 负责查询—候选联合评分，作用位置不同。与本项目三路信号 + 图补全公平比较，不把 RAG 弱化为单路向量检索。
- **图补全**：需能回答图中保存什么、关系如何形成、命中后怎样扩展、为什么可能比增加 top-k 或重排多找到信息，以及噪声与维护代价；无对照实验不断言优于混合检索或重排。
- **对话压缩谱系**：截断 / 滑动窗口、工具结果就地清理、滚动摘要、模型摘要 + 近期保留、卸载到外置记忆按需取回、长窗口 + 前缀缓存不压缩；比较触发条件、信息保留、失真风险与调用成本。
- **评测判定**：官方 Verifier（外部、检查任务真实状态）vs 文本 Judge/LLM 自评；各自治的边界与代价。
- 一手参考：[Elastic 混合检索](https://www.elastic.co/docs/solutions/search/hybrid-search)、[sbert 检索与重排](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)；它们解释替代技术，不证明本项目已采用。
