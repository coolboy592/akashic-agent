# 章节证据包：项目定位与差异

> 本包是章节事实底稿：数据、机制、踩坑、源码锚点与禁止推导。写作与验收以 `../00-README.md` 为准，通用主张边界见 `../01-fact-boundaries.md`；本包不是封闭事实清单。

## 1. 对应简历总述

> 面向个人助手场景，基于统一 ReAct 内核构建支持长期记忆、工具调用与主动交互的 Agent，针对历史事实难取用、工具定义挤占上下文及主动推送缺乏依据的问题，设计记忆检索、执行策略与端到端评测链路。

## 2. 核心判断

“收到问题—调用工具—生成回复”可以用来简要说明执行入口，但不足以讲清本项目。以下四类问题说明设计动机，不表示其他 Agent 或 RAG 方案没有相应能力：

1. **历史证据：** 当前问题依赖很久以前的信息时，怎样找到、补搜并回到原文。
2. **上下文治理：** 工具和历史持续增长时，怎样避免每轮暴露全部 Schema 与消息。
3. **主动授权：** 没有用户本轮提问时，系统凭什么打扰用户，发送依据是什么，怎样避免重复。
4. **真实验证：** 模型说“完成了”不等于任务真的完成，需要真实环境和外部 Verifier。

统一 ReAct 内核提供共同执行方式：模型提出回答或行动，宿主检查并执行工具，观察结果回到下一步判断，直到终态。它是四项能力的组合地基，不应抢占四项简历能力的主线。

## 3. 理解整体关系的参考图

下图用于定位能力关系，不是所有场景严格经过的单一路径，也不是每道面试题的回答模板。具体执行顺序、准入条件和授权在各模块解释。

```text
用户输入 / 主动事件
        ↓
长期记忆提供历史线索与来源
        ↓
上下文层选择历史、动态材料与可见工具 Schema
        ↓
统一 ReAct 执行：判断 → 工具 → 观察 → 终态
        ↓
被动回答，或经明确授权的主动发送
        ↓
保存轨迹、回执和结果，供恢复与评测归因
```

Terminal-Bench 是独立的端到端评测场景，不是每次用户交互结束后都执行的步骤；其结果也不能直接证明记忆问答或主动推荐效果。

## 4. 四条能力的输入、输出与状态边界

下表用于总览和跨章对照。它描述能力之间的接口，不表示所有请求都按同一顺序经过四项能力；Terminal-Bench 是独立的端到端评测场景。

| 能力 | 主要输入 | 主要输出 | 不负责的状态或结论 |
| --- | --- | --- | --- |
| 长期记忆与证据检索 | 当前用户消息、已提交历史、时间与会话范围 | 受控历史线索、补搜结果、带来源的原文证据 | 不把摘要或预览直接当事实；查询只读，当前未提交交互不进入学习 |
| 工具发现与上下文管理 | 注册工具目录、provider 容量、会话历史、动态记忆 | 当前请求的可见 Schema、压缩后的模型视图、可回查原始记录 | 搜索解锁不等于执行许可；压缩不证明摘要语义无损 |
| 主动交互策略 | 不可变事件信封、用户兴趣信息、最近主动历史、渠道状态 | 初筛结果、调查结论、发送或跳过终态、投递结算状态 | 兴趣准入不等于发送决定；普通正文不具备发送权；unknown 不允许盲目重发 |
| Agent 端到端评测 | 固定任务集合、隔离环境、真实 Agent 执行、官方 Verifier | 轨迹与环境证据、逐题 outcome、按 accepted 事件生成的结果投影、分层失败归因 | reward 不是模型通用能力；Provider 或 Verifier 故障不直接算 Agent 失败 |

四项能力的边界可以按三层理解：

```text
输入与事实来源
  记忆：已提交历史与来源
  工具/上下文：注册能力、历史视图与 provider 约束
  主动交互：事件身份、兴趣状态与投递状态
  端到端评测：任务定义、隔离环境与 Verifier
          ↓
统一 ReAct 执行地基
  模型判断 → 宿主准入检查 → 工具执行 → 观察回填 → 领域终态
          ↓
能力专属输出与状态
  记忆：证据结果与提交后学习
  工具/上下文：可见投影与可回查上下文
  主动交互：share / skip 与 delivery 状态
  端到端评测：accepted outcome 与故障归因
```

这里的“输入”和“输出”是能力接口的概念归纳，不是统一数据结构。记忆和工具上下文通常参与普通请求的组织，主动交互使用受限的 ReAct 回合；端到端评测复用真实 Agent 执行，但不作为每次用户交互的必经后处理步骤。

## 5. 设计取舍

### 共用执行骨架，而不是四套独立 Agent

好处是工具结果、循环边界、模型调用和错误分类可以复用；代价是不同场景仍需独立的准入、工具集合和终态约束。主动交互不能因为共用 ReAct 就复用普通回复的发送权限。

### 事实存储与模型视图分开

原始消息、工具结果和事件身份是可恢复事实；模型每次只看到按预算组织的视图。好处是可以压缩和检索而不删除原文；代价是必须维护投影与来源对应关系。

### 模型建议与程序授权分开

模型可以提出工具调用或发送建议，宿主决定该行动是否在当前工具集合、权限和状态边界内。代价是状态机更复杂，但避免把未提交的模型输出直接变成外部效果。

## 6. 可以用来引出后文的踩坑

- 召回结果没有可靠来源时，摘要无法支持原文核验。
- 工具搜索只返回文字名称时，模型知道工具却没有可调用 Schema。
- 普通 final text 被当作主动发送依据时，生成和授权边界混在一起。
- benchmark 把 Provider fallback 当成 Agent 失败时，结果数字无法指导修复。

这些是可用材料，不要求逐项塞进项目介绍。依据解释需要引出后文，不把“事实、投影、执行、验证”作为全书唯一总结。

## 7. 结果边界

本章不需要给出新的量化结果。它要帮助理解四条简历内容为何属于同一个项目，不通过列举所有插件扩大亮点。

不得声称：系统已经覆盖所有个人助手场景，或所有主动行为都绝对安全。
