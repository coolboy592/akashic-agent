# 术语与表述边界

> 本文件用于写作与审核，不是面试答案模板。目标、分工和状态以 `00-workflow-and-state.md` 为准；以下规则适用于新版各章及 Stage 6，不能因旧稿曾通过就跳过。

## 1. 统一术语

| 术语 | 本文含义 | 不应写成 |
|---|---|---|
| 统一 ReAct 内核 | 承载观察、决策、工具执行、结果回填和终态处理的共享执行骨架 | 单纯的 Prompt 模板 |
| 历史完整实现 | 主仓库 `d565ca...` 及经核对与其对应或兼容的相关插件实现 | 混合不同版本接口和后续能力的假想实现 |
| 自动注入 | turn 开始时按当前请求检索并加入受控记忆材料 | 把全部历史放进上下文 |
| 按需补搜 | Agent 在执行过程中显式调用记忆工具补充线索 | 自动注入的同义词 |
| 原文取证 | 根据真实来源身份回查原始消息或事件 | 只返回不可追溯摘要 |
| 图关联补全 | 从已命中线索扩展相关历史关系 | 独立的第三份搜索结果列表 |
| 工具目录 | 可搜索的能力元数据集合 | 当前轮全部可调用工具 |
| 当轮解锁 | 当前执行 attempt 内使命中工具进入后续实际模型请求的受限 Schema 集合，仍受容量约束 | 只返回工具名称；永久修改全局权限；保证全部命中工具同时可见 |
| 逻辑交互单元 | 用户消息、模型工具调用、工具结果及其完成边界 | 任意固定条数消息 |
| 模型摘要与近期保留 | 对较旧已完成交互生成/更新摘要，同时保留近期内容和原始记录 | 仅按固定窗口丢弃旧消息；工具协议完整就等于摘要语义无损 |
| 运行观测 | 采集、存储或展示某次运行的使用量与状态 | 已经证明某设计使效果提升 |
| 主动发送授权 | 只有显式终态动作才能触发发送 | 模型输出任意 final text 即发送 |
| 官方 Verifier | Terminal-Bench 对任务完成状态的外部判定器 | LLM 自评或文本相似度 |
| accepted projection | 从 WAL 和有效运行中生成可接受的最终任务投影 | 多次 benchmark 结果的随意拼接 |

这些区分供解释准确使用，不要求每道题都从术语定义或状态分类开始。

## 2. 可以直接使用的结果表述

- “Terminal-Bench 2.1 固定 89 题最终通过 59 题，通过率 66.3%。”
- “评测链路能够把 26 个有效失败、3 个 Provider fallback 和 1 个 Verifier 基础设施失败分开归因。”
- “Akasha 隔离重放中，9,556 条所需 embedding 全部有效，两个 hash seed 下 11 个冻结 query 得到相同 canonical logical state。”

第二、第三句分别属于闭环归因事实和隔离一致性验证，不能转写为用户效果或记忆准确率。

## 3. 必须带限定语的表述

| 想表达的内容 | 必须带的限定 |
|---|---|
| Akasha 指标 | “在隔离迁移/重放验证中” |
| 工具搜索微基准 | “在 2,000 docs/4 keywords 的局部工作负载中” |
| 20,000 token、0.74 阈值 | “历史实现采用的参数” |
| 36 小时半衰期、1.0 阈值 | “Content 主动链路的历史策略参数” |
| prompt cache | 可以解释稳定前缀和已有观测实现；具体命中率需运行统计，提升需可比实验，三者不混用 |
| LongMemEval、PersonaMem | “后续计划补做” |

## 4. 不得无依据使用的结论

- “记忆准确率显著提升。”
- “三路检索结果加权融合后返回。”
- “压缩后 token 降低了 X%。”
- “缓存命中率提升了 X%。”
- “主动推送准确率/采纳率达到 X%。”
- “系统能够自动解决新旧事实冲突。”
- “Terminal-Bench 的 3 个 fallback 和 1 个 Verifier 故障都是 Agent 做错了。”
- “历史 63/89 与当前 59/89 可以合并成更高成绩。”

效果数字只有取得支持对应主张的数据、核对口径并经确认后才能使用；实现关系和版本约束不能靠新增一个数字解除。上述限制是编写者的检查项，正文无需逐条复述“不能说”。

## 5. 学习层解释与案例标准

仅项目简短介绍保留 2～3 分钟骨架。其余内容应连贯解释项目设计，既不写逐字口播稿，也不只给答案要点或基础概念课。

- 内容顺序随问题调整；“采用方法—工作机制—选择理由—特殊情况”可帮助检查理解深度，但不能变成所有题目的四段填空。
- “事实、投影、执行、验证”可保留在项目复盘，不能作为全书统一问题结构。某个边界确实重要时解释它，随后要回到该模块独特的技术细节。
- 使用真实案例时说明现象、原因、处理和已有验证，必要时解释原假设为何失效。没有真实事故证据的内容只能作为设计风险或示例；示例必须标明，不能冒充真实用户经历。
- 不要求每章唯一踩坑，不为每题附加固定案例、验证或消融。案例不能代替正常机制讲解，只有提交号或“后来优化了”也不算解释。
- 专有名词、关键参数和短代码在有解释价值时可进入学习层；不堆叠路径与函数清单，不用整齐术语掩盖尚未理解的实现。

## 6. 问题设计：已确认的纠偏

面试官可合理知道的是简历和候选人此前的回答，不是工作台、提交历史或内部实验账本。题目应对实习生有技术考察价值，二级追问由前面的回答自然引出；不预设对方所有实现均正确，也不靠刁钻或空泛题目制造深度。

| 之前的问题 | 后续设计要求 |
| --- | --- |
| 用“事实、投影、执行、验证”串起所有题目 | 从具体技术主张出发，各模块讲自己的方法、疑点与取舍 |
| “为什么不用 RAG”只对比单路向量，或转为纠正 RAG 定义 | 正面比较常见向量＋BM25＋RRF 混合检索、必要的重排与本项目机制 |
| “有历史 63/89，为什么最终用 59/89” | 不设为默认独立面试题。历史轨道比较留内部核查；从简历 66.3% 的测量方法、成功标准和失败情况发问 |
| 泛化的“你自己完成哪些工作，原方案、改动、验证是什么” | 不作为独立核心题或所有问题的入口；通过具体实现和取舍体现理解与贡献，不虚构贡献 |
| “有限时间只能做一个实验／重做一次优先改什么”等空泛复盘题 | 不设为默认独立核心题；在已经说明的技术局限或效果主张后，自然讨论消融与改进 |
| 压缩只问“怎样不破坏工具链” | 还要解释滑动窗口、模型摘要或二者结合，压缩触发、范围、信息保留与丢失后的处理 |
| 将内部证据核查步骤直接变成追问 | 核查在工作台完成，正文讲技术问题本身 |

“为什么有引用仍可能答错”“工具搜索会不会反增 token”“为什么初筛和调查分开”等可以保留为问题来源，但不能直接复制预设问答。需要结合实现设计题干，先让答案讲清机制，再在有意义的分支深入。旧题目编号、八题/十题数量和固定追问配额均不继承。

## 7. 常见技术比较与信息缺口

### 7.1 混合检索与图补全

- 本文中的“常见 RAG 方案”应落到具体检索链路：稠密向量、BM25、RRF 排名融合以及按需要加入的重排。不以纠正宽泛定义替代方案比较，也不声称这些组件是所有 RAG 的必备配置。
- 区分 bi-encoder 的独立编码检索与 cross-encoder 的查询—候选联合评分；不要把召回、排名融合、重排和图扩展当作同一作用的互斥技术。是否使用、如何组合，须按项目实际实现解释。
- 图补全要回答图中保存什么、关系如何形成、命中后怎样扩展，以及为什么可能比增加 top-k 或重排多找到信息；也要解释噪声和维护代价。没有对照实验不能断言优于混合检索或重排。
- 技术比较可查阅 [Elastic 混合检索](https://www.elastic.co/docs/solutions/search/hybrid-search) 与 [Sentence Transformers 检索与重排](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html) 等一手资料；它们解释替代技术，不证明本项目已经采用。

### 7.2 对话压缩

已有材料支持较旧完整交互生成/更新模型摘要、近期内容保留、原始历史保留。具体摘要模型、提示词、全量重算还是增量更新、预算估算方法及失败处理，不能仅凭参数或“有摘要”推断，需要沿实现补足。

工具调用链完整只解决结构和协议问题；摘要是否遗漏约束、混淆事实或在多次更新中失真，是另一个需要解释的问题。容量重试也不等于语义失真被自动修复。

### 7.3 缓存观测与待补数据

`observe` 提供缓存观测的线索已由用户指出，公开 README 也说明缓存效率视图。讲解时应查对应版本如何取得、汇总和展示数据，解释统计口径；不能再次默认建议从零补做采集功能。

待补项要具体区分：实现细节尚未核实、已有日志尚未整理、缺少可比实验、确实缺少功能。当前命中率、token 使用量与“优化带来的提升”是不同主张。用户掌握但尚未交入工作台的数据，不自动视为不存在。

## 8. 版本与正文边界

- 全文以历史完整基线 `d565ca...` 讲解四项能力；相关插件需与其对应或兼容，研究范围可比简历广，正文重点不随插件数量扩张。
- 不混入其他版本的模块名、接口、状态结构或新增成果；插件当前页面只作线索，不能跳过版本核对。
- 原始事实与内部审查留在适合回查的材料中；正文取用能说明问题的机制、例子和结果，不写成审计报告。
