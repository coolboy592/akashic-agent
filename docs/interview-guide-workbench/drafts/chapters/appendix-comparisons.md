### 1.1 长期记忆与证据检索（记忆章）

> 简历条目：「集成并改造 Akasha 记忆引擎，融合稠密向量语义召回、BM25 词法检索与图关联补全，保留来源并对多路召回结果去重；设计『自动注入—按需补搜—原文取证』链路，使 Agent 可在摘要遗漏细节或新旧事实冲突时回源核实，支持基于历史证据回答。」

| # | 简历主张 | 实现技术 |
| --- | --- | --- |
| 1 | 集成并改造 Akasha 记忆引擎 | Akasha 以普通插件生命周期挂载（`apply`——插件装配入口）；引擎侧负责学习、图结构与读取诊断（`FeaturePool` 证据池、`read_pattern_completion` 图上补全、`learn` 图学习入口），宿主侧负责查询组织、注入预算、工具注册与来源发布 |
| 2 | 融合稠密向量语义召回、BM25 词法检索与图关联补全 | `dense_scores`（稠密相似分）与 `bm25_scores`（BM25 词法分）两路证据 → `_tail_surprisal` 排名变换 → `infer_burst_seed` 推断起始线索（`_sparsemax` 稀疏化、`context_mass` 动态混合）→ `read_pattern_completion` 图上补全；三路是职责分工协作，不是固定权重融合 |
| 3 | 保留来源 | `RecallItem.sources` 命中路径标签 → 记录级 `evidence`（类型／引用／解析器／`source_ref` 来源标识）→ `fetch_messages` 直接消费 evidence 回查原文；`wait_for_active_recall` 冻结当轮召回供回看 |
| 4 | 对多路召回结果去重 | 稠密通道（≤5 条）先选定，补全通道按稳定节点 id 对其去重后填充；同条历史两路命中以稠密条目呈现并置 `also_completed` 标记 |
| 5 | 设计『自动注入—按需补搜—原文取证』链路 | `PROMPT_RENDER_EVENT` 上的 `_inject_memory`（条数＋`inject_max_chars` 字符双层预算）→ `RecallMemoryTool`（意图／时间过滤／上限）→ `FetchMessagesTool`＋`SearchMessagesTool` 兜底；三层是职责递进，不是固定调用顺序 |
| 6 | 使 Agent 可在摘要遗漏细节或新旧事实冲突时回源核实 | 召回记录携带真实来源身份，`fetch_messages` 按其回查完整原文并可扩展前后文；预览与摘要明确不能直接作证（工具描述约束） |
| 7 | 支持基于历史证据回答 | 引用协议 `§cited:[id列表]§` 强制最终回复列出实际引用条目；三条路分工中仅原文取证可直接作证 |

| # | 简历主张 | 实现技术 |
| --- | --- | --- |
| 8 | 接入 Terminal-Bench 2.1 | 基于单步任务契约接入（`_SerializedVerifierTrial`——把官方 Verifier 收进进程级调度信道的 Trial 子类）；89 题以 `_task_set_identity`（固化任务集合身份的函数）入册 `manifest.json`（campaign 清单文件） |
| 9 | 构建真实任务运行、工具执行与官方 Verifier 评分闭环 | 单题闭环：独立环境启动真实 Agent turn → 清理冻结候选 → 官方计时外 `_prepare_verifier_runtime`（准备验证环境的协程）→ 摘要对比 → 官方 Verifier 出 reward |
| 10 | 实现逐题容器隔离 | 每题独立 Trial／Docker project／workspace／子网（`reserve_compose_network`——原子预留独立子网的函数）；`validate_isolation`（启动前校验容器隔离边界）拒绝越界挂载、Docker socket、白名单外 volume 与主机端口；`online_process_snapshot`（进程边界快照比对）前后一致 |
| 11 | 断点续跑 | `_append_campaign_event`（向 campaign 事件日志追加事件）逐条 fsync 追加 `events.jsonl`（campaign WAL 文件）；恢复校验 manifest 五项一致；`_accepted_campaign_outcomes`（从 WAL 恢复已接受结果）恢复已完成题，重复接受与损坏行报错；`accepted-results.json`（结果投影文件）按 accepted 事件原子重建 |
| 12 | 执行轨迹留存 | `agent/trace.jsonl`（逐事件执行轨迹）、turn／驱动终态、stdout、`container-resource.json`（资源证据）、`candidate-identity.json`（候选身份文件）、`verifier-bootstrap.json`（验证器引导证据）、`artifact_digests`（证据目录散列）与源码摘要 |
| 13 | 与失败归因 | 三层顺序：`_turn_was_empty_provider_response`（识别 fallback 终态）等 provider 终态判定 → 候选冻结与验证有效性（`verifier-skipped.json` 显式跳过记录）→ reward；本次 89 题中 26／3／1 分别落层 |

| 15 | 支持区分 Agent、Provider 与 Verifier 故障 | provider 四个判定函数分类供应链故障；Verifier 依赖失败按「未进入测试正文」单列；三层有效后的 reward `0` 才计入 Agent 失败 |

| # | 简历主张 | 实现技术 |
| --- | --- | --- |
| 16 | 统一注册本地与 MCP 工具 | `ToolRegistry`（统一工具注册表：维护工具实体、元数据与可搜索目录文档）；未加载目录按内置／MCP 来源分组（`get_deferred_names`——构造未加载目录的方法），注册身份与来源解耦 |
| 17 | 通过目录检索……按需暴露 Schema | 未加载目录（全量注册 − 元工具 − 当前可见）＋ `ToolSearchTool`（目录搜索工具实现）的 `select:` 精确加载与关键词查询；搜索基于目录元数据打分（`_score`），非向量语义检索 |
| 18 | ……当轮解锁…… | 搜索结果绑定注册表真实身份 → `grant_current_turn_search`（把解锁结果登记进当前尝试授权域）→ 下一次请求重建投影为新解锁工具释放槽位；`max_unlocked`（单次解锁上限＝provider 上限减一）约束解锁量，超额命中标 `capacity_limited`；`requires_turn_search`（要求每 turn 重新搜索的注册标记） |
| 19 | ……及常用工具预加载 | `ToolDiscoveryState`（会话级工具发现状态）按 LRU 维护近期解锁（历史实现每会话容量 5）；`_initial_visible_tools`（构造每轮初始可见集合）以常驻工具为运行时合同、预加载补位、超限裁剪 |
| 20 | 分层编排稳定指令与动态记忆 | 组装顺序：稳定指令 → 已提交历史／摘要 → 当前锚点 → 动态记忆 → 可见工具 Schema；动态记忆后置以延长稳定前缀，服务 provider 前缀缓存 |

| 22 | ……并保留完整交互单元 | `CommittedContextUnit`（压缩最小完整交互单位）批次闭合才可提交，切点不落在调用与结果中间；`KEEP_RECENT_TOKENS = 20_000`（近期保留，历史实现参数）；摘要带 generation／parent generation／source ref，原始历史由会话存储保留可回查 |
| 23 | 支持工具扩展与长对话执行 | 目录解耦「能力总量」与「单轮可见性」，新工具注册即入目录、无需改请求编排；压缩替换模型视图而非事实来源，长对话可回查、可恢复 |
| 24 | 记录输入 token、缓存命中率用于开销分析 | `ModelUsage`（归一化各驱动用量字段的记录结构，含 `cached_input_tokens`）与闭合执行单元关联；命中率按 token 加权口径聚合；observe 插件提供看板（版本边界见事实包） |

### 1.4 主动交互策略（主动章）

> 简历条目：「将推送决策拆为基于用户记忆的兴趣初筛与工具辅助的证据核验，在限定调查步数内决定发送或跳过；结合事件版本去重、兴趣衰减和唤醒阈值控制触发，支持不适合打扰时静默结束。」

| # | 简历主张 | 实现技术 |
| --- | --- | --- |
| 25 | 将推送决策拆为……兴趣初筛与……证据核验 | 同一 ReAct 运行时上的两个受限回合（`ToolGrant.only`——把回合工具集限定为显式列表的授权构造）：初筛回合仅 `screen_content`（初筛终态工具）、单步、读注入记忆不调查；调查回合持 `recall_memory`＋`web_fetch`＋两个终态工具、步数预算 20 |
| 26 | 基于用户记忆的兴趣初筛 | 初筛提示读自动注入记忆区块与 `PROACTIVE_CONTEXT.md`（归档的主动偏好规则）；兴趣分由 `_preprocess_interest`（提取程序化基础兴趣的函数）与 `ConversationSemanticInterest`（与已完成非主动会话做语义相似度比较的组件）按 noisy-OR 合成 |
| 27 | 工具辅助的证据核验 | 调查回合禁用 `RETRIEVED_MEMORY_SECTION`／`LONG_TERM_PROFILE_SECTION`（自动注入记忆与长期画像区块），记忆证据经 `recall_memory` 显式取回、来源经 `web_fetch` 核对；`share_content`（发送终态工具）必须引用冻结批次真实条目 |
| 28 | 在限定调查步数内决定发送或跳过 | `_INVESTIGATION_STEP_BUDGET = 20`（调查回合最大 ReAct 输出数，历史策略参数）；唯一终态 `share_content`／`skip_content`（跳过终态工具）；无有效终态按 defer 一律不发送 |
| 29 | 结合事件版本去重…… | `UNIQUE(kind, source_id, item_id, revision)`（类型—来源—条目—版本四元组唯一约束）：精确重复复用、内容冲突 fail-loud；新 revision 才成新候选；旧 revision 不能靠重扫恢复唤醒资格 |
| 30 | ……兴趣衰减和唤醒阈值控制触发 | `ContentScore`（内容兴趣分记录结构）一次评分＋读时确定性衰减（36 小时半衰期，历史策略参数）；`WAKE_ADMISSION_FLOOR = 0.02`（单条贡献底线）过滤；`should_wake`（唤醒判定）要求池质量严格超过 `WAKE_POOL_THRESHOLD = 1.0` 且批次存在新身份 |
| 31 | 支持不适合打扰时静默结束 | `skip_content` → release 归还候选、零发送；初筛无效或无有效终态 → defer 不发；低于底线条目过期清理；未过唤醒阈值不启动任何模型调用 |

| # | 选型问题 | 本项目选择（与已付代价） | 放弃／未采用的形态 | 对方更优的场景 | 出处 |
| --- | --- | --- | --- | --- | --- |
| 1 | 记忆检索信号组织 | 多信号＋图补全：稠密＋BM25 经排名变换、线索推断、稀疏化选择后在图上补全。代价：查询行为比单路检索复杂，必须保留来源标签才能解释候选 | 单路向量 top-k；持续摘要画像；长窗口硬扛；混合检索＋RRF＋cross-encoder 重排（未采用，无对照实验不断言孰优） | 单路向量＝实现与解释最简；摘要画像＝零检索轮次零工具依赖；长窗口＝单会话短任务、历史无复用价值；混合检索＋重排＝语料大、查询措辞多变、对排序质量敏感 | 记忆章 §2.3 |

| 4 | 记忆写入与一致性 | 提交后学习＋查询只读（经 `commit_gate` 提交闸门互斥）；离线重放作一致性验证手段而非在线替代品。代价：当前 turn 不进记忆（检索只在历史）、更新滞后一步 | 即时写入（读写共享状态）；模型自编辑记忆（MemGPT／Letta 形态） | 即时写入＝记忆即时生效；模型自编辑＝表达灵活、可即时纠错 | 记忆章 §2.3 |

| 6 | 工具目录检索 | 关键词打分＋`select:` 精确选择（目录元数据打分，非 embedding）。代价：查询措辞与目录元数据不一致时命中质量下降，靠 `select:` 兜底；规模上量级应升级混合检索而非替换单路 | 向量语义检索；混合检索＋重排 | 向量＝工具数百上千、查询是自然语言、名与描述语义差距大；混合＋重排＝召回上限最高、对命名混乱最鲁棒（几十个工具规模发挥不出来） | 工具章 §2.3 |
| 7 | 对话压缩 | 模型摘要＋近期保留＋可回查投影：完整交互单元边界、摘要代际、原始历史保留。适用：跨多次会话的长任务且需按引用回查原文。代价：每次压缩多一次摘要调用（需二分收缩）、失真累积、代际维护；协议完整≠摘要语义无损 | 截断／滑动窗口；就地清理工具结果（正交可叠加）；滚动摘要；卸载到外置记忆按需取回（与记忆章互补而非互斥）；长窗口＋前缀缓存不压缩 | 截断＝零额外调用、近期零失真；就地清理＝直击工具结果大头且保留协议结构；滚动摘要＝实现更简单；外置记忆＝上下文最小、保留上限最高；不压缩＝最省工程 | 工具章 §2.3 |
| 8 | 前缀缓存策略 | 稳定前缀分层：动态内容后置延长稳定前缀。代价：注入位置的表达自由受分层顺序约束；命中率有记录、提升需前后对照实验（不声称已提升） | 不做分层；显式断点标记（cache_control 一类）；自动前缀缓存（provider 侧机制） | 不分层＝请求天然无稳定前缀时零约束；显式断点＝粒度更细、可保护请求中段稳定块；自动前缀＝零改造成本。分层与 provider 两种机制正交 | 工具章 §2.3 |
| 9 | 评测判定 | 官方 Verifier：任务作者预写、在环境内运行、以最终状态为判据，跨 Agent 可比。代价：容器／验证依赖／时限运维，Verifier 自身也可能失败（本次 1 题因依赖下载未进测试正文而单列）并进入归因链 | 模型自评；文本 LLM Judge（可作叠加诊断信号，不在正式口径）；人工评估 | 自评＝零额外成本、快速冒烟；LLM Judge＝无判定器的开放式生成任务（写作、问答、对话质量）；人工＝判定上限最高、能处理模糊标准（不可扩展） | 评测章 §2.3 |
| 10 | 评测隔离粒度 | 逐题独立 Trial＋Docker project＋独立子网，配隔离校验、并发门与容量门。代价：容器创建、依赖准备与存储随题数线性增长 | 共享环境；快照复用；托管沙箱池 | 共享＝启动成本最低、依赖只装一次（题目显式无干扰时）；快照＝折中更快；托管池＝弹性与运维外移、适合大规模持续评测。隔离校验与运行位置正交 | 评测章 §2.3 |
| 11 | 结果记录与恢复 | append-only WAL（逐条 fsync）＋ accepted 事件原子投影，可随时重建。代价：投影一致性维护、读者需理解「事实在日志、视图可重建」 | 覆盖写单文件；每题独立文件＋事后汇总；中心数据库 | 覆盖写＝单题单次冒烟最简；独立文件＝部分写入风险小；数据库＝事务与查询能力强（但引入运维依赖、双处状态同步） | 评测章 §2.3 |

| 13 | 主动触发与决策 | 程序化准入（确定性）＋两阶段模型决策（初筛单步无工具／调查预算 20）＋结构化终态：把工业漏斗的分层思想搬到 agent 链路，个性化依据是可回查的用户记忆而非统计画像。代价：单条决策成本远高于打分器、两次模型调用、初筛可能漏、吞吐上限低 | 纯规则触发（Alert 职责即此形态）；单次模型判断；工业推送漏斗（召回—排序—频控，离线打分器） | 纯规则＝零模型成本、完全可解释（告警类、判定标准客观）；单次判断＝延迟与成本最低（内部低风险场景）；工业漏斗＝海量候选高吞吐下的成本分层 | 主动章 §2.3 |
| 14 | 重复与新鲜度控制 | 事件版本身份（四元组唯一约束、冲突 fail-loud）＋固定分衰减池＋唤醒需新身份。前提：上游提供稳定 identity，不配合时应降级到内容指纹而非拿标题硬扛 | 标题／URL 去重；内容指纹（simhash／minhash）；语义聚类去重 | 标题去重＝零外部依赖；指纹＝对文本变体鲁棒；语义聚类＝跨来源跨表述覆盖最广（后两者无身份语义，分不清「同条目新版本」与「另一独立条目」） | 主动章 §2.3 |

## 三、共性设计模式提炼

从四份能力章与总述章归纳五条跨模块共性。每条注明出处章节与机制支撑；模式命名是为汇总方便，各章原文未必以此自述（总述章明确自述的条目单独注明锚点）。

### 3.1 受限投影：模型视图与事实来源分离

凡进入模型上下文的材料都视为投影——可裁剪、可摘要、可按容量取舍；事实来源另行保真保存，投影可从来源重建或回查。

- 工具章：压缩摘要带 generation／parent generation／source ref 三件套，是「可追溯的投影而非新的事实源」，原始消息与执行记录由会话存储保留；可见工具集合是注册表受 provider 上限约束的投影，被裁剪工具保留在目录中可重新搜索加载。
- 记忆章：召回的预览与摘要不能直接作证，只有按来源身份回查的原文可以——检索材料对模型是线索，不是事实源。
- 评测章：`accepted-results.json` 是 WAL accepted 事件的投影、可随时原子重建；`manifest.json` 固定任务集合与源码身份，防止把部分数据投影成全量结果。
- 主动章：唤醒时冻结候选批次作为本次选择的事实来源，终态引用只能指向批次内真实条目。
- 锚点：总述章「项目最重要的工程取舍」——历史可以被压缩但原始记录保留。

边界：投影层引入投影与来源的一致性维护、跨请求状态管理与额外调用成本（工具章、评测章均明确列为此代价）。

### 3.2 显式授权与结构化终态：模型输出不等于系统动作

模型的自由生成文本不具备改变领域状态的效力；改变状态必须经带 schema 的显式动作、由宿主程序校验后执行，授权按最小范围发放且随作用域失效。

- 主动章：`share_content`／`skip_content` 是回合内唯一能推进领域状态的出口，程序校验引用合法性与终态唯一性，无有效终态一律不发；两阶段的工具授权用 `ToolGrant.only` 精确限定，阶段间互相够不到对方权限。
- 工具章：registered／visible／executable 三态只正向递进不反向豁免；当轮解锁只改可见性不改执行准入，授权域按 turn＋attempt 划分、尝试结束即失效；`requires_turn_search` 强制每 turn 重新授权。
- 评测章（同一思想的评测侧）：接受 Agent 结果前先由程序读真实回合与轨迹确认 provider 终态，不采信运行时返回的文本。
- 锚点：总述章——工具可以被搜索但搜索不等于执行许可，模型可以建议发送但普通正文没有发送权限。

### 3.3 证据可回查：结论携带到达证据的路径

系统产出的每条可陈述结论（回答引用、评测归因、推送决策、历史摘要）都保留指向原始证据的链路，事后可复核「这条结论用了哪些证据」。

- 记忆章：`RecallItem.sources` 命中路径标签 → 记录级 `evidence`（含 `source_ref`）→ `fetch_messages` 回查原文；`wait_for_active_recall` 冻结当轮召回供「这条回答受哪些记忆影响」回看；回复末尾的 `§cited` 引用协议。
- 工具章：摘要 source ref 指向覆盖的原始范围、可按引用回查；用量记录与闭合执行单元关联。
- 评测章：`agent/trace.jsonl`、turn／驱动终态、候选摘要、验证器引导证据全套留存；三类故障的区分「全部可回查 trace 与终态记录，不靠最终文本猜」。
- 主动章：`WakeState`（Wake 逐次运行状态库）落库初筛候选与最终决策；`skip_content` 的 reason 留内部审计；终态必须引用真实事件项。
- 锚点：总述章——换来的是可回查证据和可归因的失败。

边界：可回查证明「结论有据可查」，不证明结论正确——记忆章明确「来源只给核验入口，不给正确性」，新旧事实冲突不由系统自动判定。

### 3.4 外部判定：有效性由系统侧独立检查确立，不由模型自我报告确立

一个结论是否成立，锚定在模型之外的可观察事实上（环境最终状态、真实请求 payload、程序校验结果）；模型自评与表面文本只作诊断输入。

- 评测章（本模式的最强形态）：官方 Verifier 以环境最终状态为判据（文件内容、进程状态、测试通过），模型自评与 LLM Judge 只能对文本表态；trace 与文本在闭环内只作诊断输入。
- 主动章：终态推进靠程序校验（引用在冻结批次内、唯一性），程序不猜测模型意图；调查阶段禁用自动注入、证据必须经工具显式取回，「读到的画像」与「查过的证据」分开。
- 工具章：搜索解锁的回归断言落在下一轮真实请求携带的 Schema 与执行次数上——「只断言搜索文本包含工具名，这个缺陷测不出来」；摘要输出经 `SUMMARY_HEADINGS`（摘要必须匹配的固定标题结构）程序校验。
- 记忆章：三条检索路中哪条可直接作证由工具职责结构决定（仅原文取证），不是模型的自我判断。
- 锚点：总述章——自建的收益是把模型建议、宿主执行、状态变化和结果观测放在同一条可检查的边界内。

### 3.5 成本与确定性分层：规则前置、模型调用受限后置

先用廉价的确定性规则过滤与定序（身份、去重、阈值、预算），模型判断只在规则放行后进入，且每次进入都带受限的工具集、步数或条数预算；昂贵操作随不确定性递增。

- 主动章：程序化准入（衰减池、阈值、新身份）只决定「值得花模型成本」→ 初筛单步无工具 → 调查预算 20 步 → 结构化终态；未过唤醒阈值不启动任何模型调用。
- 记忆章：自动注入（双层预算、低摩擦给线索）→ 按需补搜（更具体查询）→ 原文取证，「取证成本随不确定性递增」；三层是职责递进不是固定调用顺序。
- 工具章：LRU 预加载消除高频工具的重复搜索摩擦（只影响初始投影候选，不是授权）；几十个工具规模用关键词打分而非向量基建。
- 评测章：重试只覆盖限流与瞬时故障（确定性分类），Agent 失败不重试刷分；归因顺序固定，三层都有效才读 reward。

边界：分层引入更多状态与调用轮次——主动章明确认账：两次模型调用、初筛可能漏掉有价值内容、两阶段不如单次判断快。
